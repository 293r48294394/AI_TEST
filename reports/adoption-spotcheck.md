## TC-007 用户首次领取公开券成功，库存扣 1 并生成用户券

出处：PRD 4.2.1、4.2.2、7 表 7-1 说明③

- [ ] 库存由 100 扣减为 99（成功领取必须扣 1）
- [ ] 生成 1 条用户券记录，状态「未使用」
- [ ] 领取失败/成功都有埋点，`coupon_receive` 带 **stock_before 与 stock_after，差值必须为 1**
- [ ] 同一 `userId + couponId + requestId` 重复提交只发一张（6.2 幂等）

> **初判：不足** — 用例验了库存和用户券，但**没有断言 `coupon_receive` 埋点的 stock 差值**，也没覆盖幂等。

## TC-008 同用户同券模板第 4 次领取返回限领错误且库存不变

出处：PRD 4.2 表 4-2 + 脚注①

- [ ] 限领口径是**跨活动累计** 3 张（不是单活动）
- [ ] 第 4 次返回 `COUPON_LIMIT_EXCEEDED`
- [ ] 库存**不扣减**（拦截发生在扣减之前）
- [ ] 用户券记录不新增
- [ ] 上报 `coupon_receive_blocked`，`ext.reason=USER_LIMIT`

> **初判：充分** — 四步把"拦截 + 不扣库存 + 不新增 + 埋点 reason"全断到了。

## TC-009 兑换码第 500 次成功、第 501 次返回 CODE_EXHAUSTED

出处：PRD 9 待定问题 Q2 答复

- [ ] 全局累计上限 500，第 500 次成功
- [ ] 第 501 次返回 `CODE_EXHAUSTED`，不生成用户券
- [ ] 兑换码**忽略大小写、去除首尾空格**（Q2）
- [ ] **同一码同一用户限兑换 1 次**（Q2）

> **初判：不足** — 覆盖了全局上限，但没测"同码同用户限 1 次"这条独立约束。

## TC-016 商品券与运费券叠加，先商品后运费且运费券不参与门槛

出处：PRD 4.3 表 4-3 脚注②、4.3.4

- [ ] 顺序：先商品券、后运费券
- [ ] 运费券**只抵扣运费**，不抵扣商品金额
- [ ] 门槛计算**不含运费**
- [ ] 应付金额与分单位计算正确（12000−2000+1200−1000=10200）

> **初判：充分** — 顺序、范围、门槛、金额四项都断言了。

## TC-018 单笔订单选 2 张商品券返回 COUPON_CONFLICT，选 3 张返回 COUPON_COUNT_EXCEEDED

出处：PRD 4.3.5

- [ ] 单笔最多 2 张：商品券 1 + 运费券 1
- [ ] **先校验数量**，超限返回 `COUPON_COUNT_EXCEEDED`
- [ ] 未超限再校验互斥，两张商品券返回 `COUPON_CONFLICT`
- [ ] 单张券正常下单（对照组）

> **初判：充分** — 连"先数量后互斥"的判定顺序都用 3 张券的用例覆盖了。

## TC-022 核销请求 nonce 已使用或时间戳超 ±5 分钟返回 REPLAY_REJECTED

出处：PRD 4.4.3

- [ ] 同一 nonce 重放 → `REPLAY_REJECTED`，券状态不变
- [ ] 时间戳早于窗口 1 秒 → 拒绝
- [ ] 时间戳晚于窗口 1 秒 → 拒绝
- [ ] **正好 ±5 分钟边界 → 通过**（边界不能一刀切拒）

> **初判：充分** — 重放 + 两个方向的越界 + 边界值，是这类防护最完整的测法。

## TC-026 部分退款返还计算为 0.004 元时，兜底按 0.01 元入余额

出处：PRD 4.4 表 4-4 脚注④

- [ ] 返还额 = 优惠金额 × 退款金额 ÷ 订单实付，保留 2 位、HALF_UP
- [ ] 结果低于 0.01 元时**按 0.01 元返还**
- [ ] 返还**以余额入账**
- [ ] **不重新发券**（脚注④明文）
- [ ] 埋点 `coupon_refund.return_amount` 与实际入账一致

> **初判：不足** — 少一个"不重新发券"的负向断言；实现若顺手补发一张券，这条用例抓不到。

## TC-028 整单退款后券保持已使用，且优惠计入已核销营销成本

出处：PRD 4.4 表 4-4「整单退款（全额）」行 + 脚注④

- [ ] 券状态保持「已使用」，不恢复「未使用」
- [ ] 优惠金额**不返还**给用户
- [ ] 优惠金额计入**已核销营销成本**
- [ ] 实付 100 元**原路退回支付渠道**（不是退回余额）
- [ ] 用户余额不增加（负向断言）

> **初判：不足** — 验了券、余额、成本三处，但没断言"退款走原支付渠道"，只写了"接口返回成功 100 元"。

## TC-032 券到期日 23:59:59 当秒可用，次日 00:00:00 返回 COUPON_EXPIRED

出处：PRD 5 表 5-1 脚注⑤、4.6.2

- [ ] 结束时间 23:59:59 **当秒仍可用**
- [ ] 次日 00:00:00 起失效，返回 `COUPON_EXPIRED`
- [ ] 判定以**服务端 Asia/Shanghai** 为准
- [ ] 试算与下单两个入口都拦截

> **初判：充分** — 两个时点 + 两个入口 + 错误码，边界测得住。

## TC-039 coupon_verify 异步上报延迟 ≤5s，超 5s 由对账标记缺失并告警

出处：PRD 7 表 7-1 说明③

- [ ] 正常链路：埋点上报延迟 ≤ 5s
- [ ] 超 5s：次日 02:00 对账标记「埋点缺失」并告警
- [ ] **核销结果不回滚**，券状态仍为已核销

> **初判：充分** — 正反两条链路 + "不回滚"这个关键副作用都写了。

## 怎么用这张表（3 分钟）

1. 逐条读用例（界面「③ 用例」里点行首箭头展开），对照勾选框
2. 全勾 → 写 `充分`；有任意一条没断到 → 写 `不足`
3. 把 10 个结论发我，我算两个数写进 README：
   - 采纳率 100%（30/30）
   - **断言充分率 X/10**

> 口径说明：`充分` ≠ 用例写得差。它只说明"这条规则还有约束没测到"——
> 这类缺口正是人工该补的地方，也是 HITL 闸门存在的理由。
