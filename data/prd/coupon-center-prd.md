## 2. 背景与目标

券能力此前分散在三个系统，模板字段、库存口径与核销逻辑各不相同，一次发券活动平均需 2 人日，且多次出现超发与重复核销。本版本收敛到营销中心，统一模板、库存与核销链路。

目标：2027 年 Q1 末券核销率由 48% 提升至 65%，券创建配置时长由 2 人日降至 0.5 人日，超卖事故为 0。

## 3. 角色与权限

表 3-1 角色与权限

| 角色 | 可执行操作 | 数据范围 | 明确禁止 |
| --- | --- | --- | --- |
| 平台运营 | 创建发布平台券、审核商家券 | 全平台 | 修改已核销券的状态与金额 |
| 商家 | 创建店铺券、定向发放、看本店报表 | 仅本店商品与类目 | 创建全场券或平台券 |
| 用户 | 领取、下单使用、未使用且未过期可退券 | 仅本人 | 转让、提现、修改面额 |
| 客服 | 查询用户券、补发补偿券、人工退券 | 全平台只读 + 补偿 | 创建活动、改核销状态 |

脚注（表 3-1）：商家创建店铺券时，单活动预算不得超过店铺保证金的 20%，超出返回 BUDGET_EXCEEDED；平台券创建接口仅对平台运营开放，商家调用返回 403 / ROLE_FORBIDDEN。客服补偿券占用预算，不计入限领次数（见 4.2 表 4-2 脚注①）。

## 4. 功能需求

### 4.1 优惠券创建

4.1.1 券模板支持满减、折扣、立减三类，字段见表 4-1。

表 4-1 券模板字段

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| 券名称 | 文本 | 是 | 2–20 字，活动内唯一 |
| 券类型 | 枚举 | 是 | 满减 / 折扣 / 立减 |
| 面额或折扣率 | 金额 / 小数 | 是 | 满减 0.01–5000 元；折扣 0.80–0.99；立减 0.01–500 元 |
| 使用门槛 | 金额 | 条件必填 | 满减与折扣必填且 ≥ 0.01 元；立减固定 0.00 |
| 适用范围 | 枚举 | 是 | 全场 / 指定类目（≤50）/ 指定商品（≤500） |
| 发放方式 | 枚举 | 是 | 公开领取 / 定向发放 / 兑换码 |
| 发放总量 | 整数 | 是 | 1–1,000,000 |
| 有效期 | 时间段 | 是 | 开始早于结束，最长 180 天 |

4.1.2 立减券无门槛，门槛固定 0.00，前端不渲染输入框。

4.1.3 折扣率区间 [0.80, 0.99]，超出返回 COUPON_DISCOUNT_INVALID；券发布后仅可下架，不可改面额、门槛与适用范围。

### 4.2 用户领取

4.2.1 公开领取：校验登录态、活动状态、库存与限领规则，通过后扣减库存并生成用户券。

4.2.2 库存不足返回 COUPON_SOLD_OUT，不生成用户券，提示「来晚了，已被领完」。

4.2.3 时间窗：开始前 1 秒返回 COUPON_NOT_STARTED，开始当秒可领；结束当秒仍可领，次日 00:00:00 起返回 COUPON_ENDED。

4.2.4 兑换码：用户输入 12 位码，校验通过后生成用户券，码状态置为「已使用」。

4.2.5 定向发放：按用户 ID 导入，单次最多 10 万条；越权领取 403。

表 4-2 限领规则

| 维度 | 阈值 | 错误码 |
| --- | --- | --- |
| 单用户单券 | 3 张 | COUPON_LIMIT_EXCEEDED |
| 单用户单活动 | 5 张 | COUPON_ACTIVITY_LIMIT |
| 单券总发放量 | 等于发放总量 | COUPON_SOLD_OUT |

脚注①（表 4-2）：单用户限领 3 张为跨活动累计口径，同一券模板下所有活动合并计算；客服补偿券不计入该次数。第 4 次领取在库存扣减之前拦截，返回 COUPON_LIMIT_EXCEEDED，库存不变，并上报 coupon_receive_blocked（ext.reason=USER_LIMIT）。

### 4.3 下单使用

4.3.1 结算页按抵扣降序展示，默认选中抵扣最多的一张，可切换。

4.3.2 试算入参为商品金额、运费与券 ID，返回抵扣与应付金额，单位分，展示两位小数。

4.3.3 支持商品券与运费券叠加，组合以表 4-3 为准。

4.3.4 门槛计算以订单商品金额为基础，口径见表 4-3 脚注③。

4.3.5 单笔订单券数量上限为 2 张：商品券 1 张、运费券 1 张；超限直接返回 COUPON_COUNT_EXCEEDED，未超限再校验互斥，两张商品券返回 COUPON_CONFLICT。

4.3.6 三端调用同一试算接口，前端只做展示，不得二次取整。

表 4-3 叠加与互斥矩阵

| 券 A \ 券 B | 满减券 | 折扣券 | 立减券 | 运费券 |
| --- | --- | --- | --- | --- |
| 满减券 | 互斥 | 互斥 | 互斥 | 可叠加 |
| 折扣券 | 互斥 | 互斥 | 互斥 | 可叠加 |
| 立减券 | 互斥 | 互斥 | 互斥 | 可叠加 |
| 运费券 | 可叠加 | 可叠加 | 可叠加 | 互斥 |

脚注②（表 4-3）：折扣券与满减券不可叠加，同属商品券，同订单只能用一张；商品券可与运费券叠加，顺序为先商品后运费，运费券仅抵扣运费，不参与商品门槛计算。

脚注③（表 4-3）：门槛金额取「商品实付金额」= 商品金额 − 已生效的其他优惠（不含运费、礼品卡、积分抵扣）。比较使用 BigDecimal，保留 2 位小数、HALF_UP；恰好等于门槛视为达标。

### 4.4 支付与核销

4.4.1 支付成功回调到达后即时核销，券状态置「已使用」，记录核销时间与订单号。

4.4.2 同一张券同一订单重复核销返回 COUPON_ALREADY_VERIFIED，仅保留一条核销流水。

4.4.3 核销接口需携带 nonce 与时间戳（±5 分钟），重放返回 REPLAY_REJECTED。

4.4.4 退款按整单与部分分别处理，见表 4-4。

表 4-4 退款返还规则

| 退款类型 | 券状态 | 优惠金额处理 |
| --- | --- | --- |
| 整单退款（全额） | 保持「已使用」 | 券不返还，优惠金额计入已核销营销成本 |
| 部分退款 | 保持「已使用」 | 按比例返还至用户余额（见脚注④） |
| 支付超时关单 | 恢复「未使用」 | 不涉及金额返还，有效期不延长 |

脚注④（表 4-4）：部分退款返还金额 = 券优惠金额 × 退款金额 ÷ 订单实付金额，保留 2 位小数、HALF_UP；结果低于 0.01 元时按 0.01 元返还；返还以余额入账，不重新发券；整单退款不返还任何优惠金额。

### 4.5 订单关闭/超时释放

4.5.1 订单创建后 30 分钟未支付自动关单，关单时释放券与库存，券恢复「未使用」。

4.5.2 关单接口幂等，重复请求返回首次结果，不重复释放。

4.5.3 用户主动取消订单：券退回账户，订单置为「已取消」。

### 4.6 过期与失效

4.6.1 定时任务每 5 分钟扫描到期券，置为「已过期」，列表不再展示为可选。

4.6.2 使用已过期券提交订单返回 COUPON_EXPIRED。

## 5. 业务规则

表 5-1 业务规则

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| BR-01 | 金额精度 | 以分存储，BigDecimal 计算，保留 2 位小数、HALF_UP |
| BR-02 | 有效期判定 | 以服务端时间为准，时区 Asia/Shanghai，到期 23:59:59 |
| BR-03 | 库存一致性 | Redis 计数器 + DB 流水，允许最终一致，02:00 对账修正 |
| BR-04 | 限领口径 | 跨活动累计，客服补偿券除外 |
| BR-05 | 退券 | 仅未使用且未过期可退，已占用限领次数不退 |
| BR-06 | 商家券审核 | 需平台运营审核，时长 ≤ 1 个工作日 |

脚注⑤（表 5-1）：有效期按服务端 Asia/Shanghai 判定，结束时间 23:59:59 当秒仍可用，00:00:00 起失效；海外用户端按浏览器时区展示本地时间，但可用性判定以服务端时区为准，前端不得换算后判定。

脚注⑥（表 5-1）：折扣券应付 = 商品实付金额 × 折扣率，保留 2 位小数、HALF_UP；满减与立减直接减面额，不做舍入；优惠后应付最低 0.01 元，不足按 0.01 元收取。

## 6. 非功能要求

6.1 并发：领取峰值 5000 QPS，P99 ≤ 200ms；1000 张库存不超卖、无负库存。

6.2 幂等：领取（userId + couponId + requestId）、核销（券 ID + 订单号）、关单（订单号）三类操作必须幂等。

6.3 批量核销：1 万笔在 5 分钟内完成，失败率 < 0.01%，失败记录进入重试队列。

6.4 对账：每日 02:00 对账 Redis 库存、DB 券流水、支付流水，差异率 > 0.1% 告警。

6.5 时区：服务端以 UTC 存储，展示与判定使用 Asia/Shanghai。

## 7. 数据埋点

表 7-1 埋点清单

| 埋点 | 触发时机 | 关键字段 |
| --- | --- | --- |
| coupon_receive | 领取成功 | coupon_id, user_id, stock_before, stock_after |
| coupon_receive_blocked | 领取失败 | reason（USER_LIMIT / SOLD_OUT / NOT_STARTED） |
| coupon_use | 下单选中券 | order_id, discount_amount |
| coupon_verify | 核销成功 | coupon_id, order_id, verify_time |
| coupon_refund | 退款返还 | refund_amount, return_amount |

说明③（表 7-1）：coupon_receive 必须带 stock_before 与 stock_after，差值必须为 1，否则按埋点异常告警；coupon_verify 异步上报，延迟 ≤ 5s，超 5s 未上报由每日对账标记「埋点缺失」并告警，核销结果不回滚。

## 8. 异常与边界清单

表 8-1 异常与边界

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| EX-01 | 库存为 0 时并发领取 | 全部返回 COUPON_SOLD_OUT，无负库存 |
| EX-02 | 券已过期但缓存未刷新 | 以 DB 为准，返回 COUPON_EXPIRED |
| EX-03 | 支付回调延迟 10 分钟 | 仍核销，时间取回调到达时间 |

| EX-06 | 兑换码含空格或小写 | 去首尾空格并转大写后校验 |
| EX-07 | 用户时区为 UTC−5 | 展示本地时间，判定用服务端时区 |

## 9. 待定问题

Q1：券预算超支后是否自动停发？—— 待运营确认，暂定使用率达 100% 时停发告警。

Q2：兑换码字符规范与使用上限？答复：统一 12 位大写字母与数字，输入忽略大小写并去除首尾空格；同一码同一用户限兑换 1 次，同一码全局累计上限 500 次，第 501 次返回 CODE_EXHAUSTED。

Q3：部分退款后券是否返还？答复：见 4.4 表 4-4 脚注④，按实付金额比例返还至余额，最低 0.01 元，整单退款不返还。

Q4：客服补偿券是否占用预算？答复：占用店铺预算，但不计入用户限领次数。
