# 基准集复核指南

> 目标：把 42 条「AI 起草 + 机器质检」变成「人工标注」。
> 你的产出不是"点 42 个通过"，而是**每一条的判断理由**——判断不用写进文件，但有疑问的条目要写。

---

## 一、先明确：`通过/改/删` 是结论，不是标准

判定标准是下面五条。逐条过一遍，**任意一条不过**才落到「改」或「删」：

| # | 标准 | 要问自己的问题 | 不过时怎么办 |
|---|---|---|---|
| 1 | **出处真实且支持它** | PRD 原文那一句，真的能推出这条测试点吗？ | 出处写错 → 改；原文根本没这规则 → 删 |
| 2 | **可判定** | 标题里有没有"什么条件 + 看什么结果"？ | 补条件（改标题） |
| 3 | **可观测** | 期望结果里有能断言的东西吗（状态码/字段/提示文案/埋点/数值）？ | 补断言点（改期望） |
| 4 | **不重复** | 和别的条目是不是同一场景（看语义，不是看字面）？ | 保留更具体的一条，删另一条 |
| 5 | **分类正确** | 六类里选对了吗？边界 vs 异常最容易混 | 改分类 |

**边界 vs 异常怎么分**：边界是**合法范围的两端**（恰好 100 元、第 3 张、59 秒、第 7 天整）；
异常是**非法输入或非法状态**（金额 -1、券已过期、参数缺字段、越权调用）。

---

## 二、三种判定各自的含义

| 判定 | 含义 | 你必须做什么 |
|---|---|---|
| **通过** | 五条全过，一个字都不用改 | 只写 `通过` |
| **改** | 场景值得保留，但标题/期望/出处/分类要修 | **必须写出改成什么**（`标题=...; 期望=...`），否则等于没审 |
| **删** | 场景不成立：PRD 没这条规则 / 与别条重复 / 是实现细节不是需求约束 / 无法验证 | 写一句理由，便于以后回溯 |

> 删掉不是"丢数据"。一条站不住的基准点会让召回率虚高，删掉它反而让指标更可信。

## 三、三个真实例子（用你仓库里的条目）

### 例 1：G-007 → 通过

| 字段 | 内容 |
|---|---|
| 标题 | 满100减20商品券与8元运费券叠加时先算商品券再算运费券 |
| 出处 | PRD 4.3 表 4-3 脚注② |
| 期望 | 20元商品券先抵扣，8元运费券再抵扣运费，应付=100.00+0.00；运费券抵扣不改变商品券抵扣额，coupon_use 记录两笔 |

怎么判：
- 出处：脚注②确实写了"折扣券与满减券互斥、运费券可叠加、先商品后运费" → **支持**这条场景；
- 可判定：标题给了两个券和顺序 → 能测出对错；
- 可观测：`应付=100.00`、`coupon_use 记录两笔` 都能断言；
- 不重复、分类（normal）也对 → **通过**。

### 例 2：G-009 → 通过

标题"30分钟未支付自动关单后券恢复为未使用"，期望写着「订单状态已关闭 / 用户券未使用 / **有效期保持原值不延长** / 支付流水为空」。
"有效期不延长"是容易被漏掉的约束（AI 常写"券恢复"就完事），它出现在期望里 → 可观测，**通过**。

### 例 3：虚构的反例（说明"改"怎么写）

假设某条是：
```
标题：优惠券使用功能正常
期望：返回成功
出处：PRD 4.3
```
五条里 2、3 不过，4.3 也只是章节不是具体依据。判定：

```
G-0XX 改 标题=满100减20券在订单金额100.00元时抵扣20.00元; 期望=HTTP 200，应付金额=80.00，coupon_use 新增1条记录，券状态变为已使用; 出处=PRD 4.3 表 4-3
```

## 四、四种常见犹豫，怎么定

| 情况 | 判定 | 理由 |
|---|---|---|
| 场景对，但期望写得太弱（"返回成功"） | **改**，别删 | 场景有价值，补断言点即可 |
| 场景对，但分类选错（比如边界写成异常） | **改** | 分类影响"按类别召回"这个指标 |
| 出处是正文条款，但实际规则在脚注 | **改**：`出处=PRD 4.3 表 4-3 脚注②; 隐性=true` | 隐性规则的召回率是核心指标之一 |
| 两条高度相似 | 留更具体的一条，**删**另一条 | 重复会让召回虚高（机器只能查字面相似，语义重复要你判） |

## 五、操作步骤（Excel 版，约 20–30 分钟）

```bash
cd ai-testcase-platform

# 1) 生成 Excel 复核表（PRD 原文逐行展开、保留换行、结论列带下拉）
python run.py review-export --golden data/golden/coupon-golden.json --out reports/golden-review.xlsx

# 2) 用 Excel 打开 reports/golden-review.xlsx
#    - G 列「结论」下拉选 通过 / 改 / 删（留空 = 未判定，导入会报错）
#    - 结论=改 时在 H 列写：标题=xxx; 期望=xxx; 分类=boundary（只写要改的字段）
#    - 结论=删 时在 H 列写一句理由
#    - 「说明」页 B1 填你的名字
#    - I 列是可以直接读的 PRD 原文（4.1 的表格已逐行展开成「字段 ｜ 类型 ｜ 必填 ｜ 约束」）

# 3) 先试跑：只校验不写盘
python run.py review-import --golden data/golden/coupon-golden.json --xlsx reports/golden-review.xlsx --dry-run

# 4) 42 条判完、质检 0 error 后写入
python run.py review-import --golden data/golden/coupon-golden.json --xlsx reports/golden-review.xlsx
```

> 也可以用纯文本版（`review-apply`）：`reports/golden-review.txt` 每行写判定。
> 两种入口走同一个质检闸门（`apply_with_gate`），行为一致。

第 4 步会做三件事，任何一件不满足都**拒绝写盘**：

1. 42 条必须全部有判定（想先做一半就加 `--partial`）；
2. 应用后自动跑基准集质检，**0 error 才写**（改了出处但章节不存在、分类写错，都会被拦）；
3. 写入时把 `annotator` 改成你的名字、`version` 改成 `v1.0`、加 `review_status: human-reviewed`。

### 为什么不用手改 markdown 表

`reports/golden-review-sheet.md` 是纯文本备份，里面的表格会被压成一行（`字段 ｜ 类型` 之间没有换行），
复制到 Excel 后很难读。**Excel 版才是为人工复核设计的**：单元格保留换行、表格逐行、结论可下拉、填完能导回。

## 六、怎么证明这是"人工"标注的

```bash
git diff data/golden/coupon-golden.json
```

你会看到每一条 `改`/`删` 的具体差异 + `annotator` 的变更。这份 diff 就是证据：
面试时说"这 42 条我逐条核过，改了 N 条、删了 M 条，理由在这里"，比任何形容词都有力。

---

## 七、复核之后会发生什么

1. 质检仍是 0 error → 基准集可以被称为"人工标注"；
2. 重跑评测，README 里的数字才算数（召回率可能下降——**下降才是正常的**，因为删掉了站不住的条目）；
3. 你的 `改/删` 会被记成"人工纠偏"证据，用于回答"AI 哪里不行"。
