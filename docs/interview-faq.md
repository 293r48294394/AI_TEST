# 面试问答包（按当前真实能力边界写）

规则先摆在这里：

- 每题先给 **30 秒版**，被打断就停。追问再展开。
- **所有数字必须来自 `reports/` 或命令输出**。没跑过的说"还没测"，不要说"大概"。
- 当前仓库里的评测数字全部来自 **离线启发式基线（mock）**，它证明的是管道与指标可用，
  **不代表模型能力**。真实模型数字要等你配 key 后跑 `--judge llm`。
  这一点在面试里主动讲，比被问出来强得多。

---

### Q1. 用一分钟介绍这个项目

> 它把「PRD → 测试点 → 用例 → 评审」拆成四个可单独验证的 Skill，串成带人工确认闸门的流水线。
> 每一步的输出都要过 JSON 契约校验（含"只能引用检索到的证据块"），评审不过就禁止导出。
> 我另外做了三件事让它可被衡量：42 条基准集、三模式对比评测、以及把评测指标和评审分分开看。
> 结果最有意思的是：规则基线的评审能到 89 分 pass，但对人工基准只有 2.4% 召回——
> **评分高不等于有用**，所以评测必须独立于评审。

证据：`README.md`、`reports/eval-coupon-center-prd-*.md`

---

### Q2. 为什么不用 LangGraph？是不是不会？

> 这条流水线只有 5 个节点、1 个人工闸门、1 个循环点。显式状态机 200 行写完，
> 每步可断点、可单测，`events.jsonl` 里能看到耗时和重试次数。图框架会把它变黑盒，
> 而我要证明的恰恰是"每一步都被验证过"。Skill 层是纯函数，真要换，把 `_stage_*` 换成 node 就行。

追问"我们公司用 LangGraph"：接"团队统一技术栈收益更大，我按你们的 node 约定改，接口是协议化的"。

证据：`atp/pipeline/orchestrator.py`（状态机）、`events.jsonl`

---

### Q3. 为什么不用向量库？

> 需求文档是关键词密集、术语精确的语料（限额、幂等、脚注编号）。BM25 + 符号加权在这个场景
> 召回不输小模型 embedding，而且**每条召回都能指回原文块**，引用校验才做得下去。
> 更要紧的是可复现：换一版 embedding 就换一套评测结论，那不叫评测。
> `Retriever` 是 Protocol，接 Chroma 只需实现 `retrieve()`，评测脚本不用改。

别说"装不上所以没用"。可以说"这台机器 pip 受限，正好逼我把依赖想清楚"，但主因是技术判断。

证据：`atp/retrieval/bm25.py`、`tests/test_retrieval.py`

### Q4. 你怎么防止 AI 幻觉？

四层，从便宜到贵：

1. **契约**：输出必须过 pydantic，多一段解释就失败重试；
2. **引用完整性**：`sources[].chunk_id` 只能取本次检索返回的 id，编造 `P-9999` 会被打回；
3. **可追溯**：评审层查"测试点有没有证据""用例有没有对应测试点"，孤儿用例是 blocker；
4. **人审**：闸门挡在生成用例之前；评审 `revise` 时导出接口返回 409。

**追问"触发过几次"**：mock 下是 0 次——规则基线本来就不会编 id，这个数字没有意义。
真实模型的触发次数是我 W1 要观察的第一项，现在没有数据，不能给。

证据：`atp/llm/schema.py`、`tests/test_schema_repair.py`（用假客户端验证四层都会触发）

### Q5. 人工确认节点到底有没有用？有数据吗？

> 机制是完整的：闸门会阻塞下游、改动被 diff 记录、导出受评审闸门约束。
> 但**量化收益还没有**：评测里的 `rag_hitl` 是"录制回放"——回放一份落盘的人工修改版测试地图，
> 保证可复现，不是本次实时人审。

我有一条真实的人工改动记录（样例在 `docs/examples/hitl-diff-example.json`）：
新增 1 个功能（券预算控制）、在 F-01 补 1 条规则，summary 是 `+1 / -0 / ~1`。
这说明"改了什么"能被审计，但不能说明"改完效果提升多少"。

**不能说**："人工确认让召回提升了 X%"——没测过。

### Q6. Match Rate 怎么算？0.55 的阈值怎么来的？

> 一对一贪心：每条基准点找最相似的生成点，相似度 = 归一化标题相似度 与「标题+期望」文本相似度取大，
> 类别相同 +0.08，边界/异常互认 +0.02；过阈值即命中，且每条基准点最多被命中一次。

阈值 0.55 是初始值，**敏感性已经做了**（`--sweep`）。当前基线在 0.80 才断崖到 0，
说明这条曲线对阈值不敏感——但也说明基线匹配本身很脆。真实模型下的曲线才有解释价值。

证据：`atp/eval/metrics.py::sweep_threshold`、`tests/test_eval_judge.py`

### Q7. Fidelity 是什么？可信吗？

> 它回答"命中之后，语义上真的忠实吗"。两套实现：
> 1）启发式代理：只看关键数字/状态有没有被带入，属**保守下限**；
> 2）`--judge llm`：1–5 分语义评判（5=全覆盖、3=漏关键约束、1=含幻觉）。
>
> 现在默认用代理。judge 的代码和一致性检查（`agreement_with_human`）都写了，
> 但**还没做过与人工评分的致率抽检**，所以我不敢说 judge 可信——抽检 ≥80% 才敢引用它的分。

证据：`atp/eval/judge.py`、`tests/test_eval_judge.py`

### Q8. 基准集谁标的？凭什么信它？

> 42 条由 AI 依据 PRD 起草，再由测试工程师**逐条复核**：39 条通过、3 条修正，
> 修正记录在 `docs/examples/golden-review-applied.diff`（每条改动的原文对比）。
> 三道保障：机器质检 14 条规则（来源可定位/标题可判定/期望可观测/场景去重，当前 0 error）、
> 人工复核（有 git diff 可查）、以及复核结论落盘后 `annotator`/`version`/`review_status` 一并写入。

复核真正抓出来的是**同一类错误**：AI 会写出 PRD 里没有的 UI 行为——
比如"冲突券置灰不可选""提示差 0.01 元可用"，读起来非常合理，但需求文档从没定义过，
这种断言一旦执行就会误报。另有 1 处分类错误（全局兑换上限被标成 security，实为 boundary）。

**要说清楚的局限**：只有一位复核人，没做交叉复核，标注者间一致性（κ）未测。
一人复核能消掉"AI 编造"这类错，消不掉个人理解偏差。

证据：`docs/examples/golden-review-applied.diff`、`atp/eval/golden_lint.py`、`tests/test_golden_lint.py`

### Q11. 你怎么知道它不只对一份文档有效？

> 我加了第二份 PRD（账号登录/安全），跨域跑一遍。它抓到两个真实过拟合：
> 1）基线的功能识别是关键词白名单（领取/创建/支付…），在账号域只识别出 2 个功能，
> 改成"章节标题 + 目录类排除"后恢复 4 个；
> 2）`s2` 提示词里用"券已过期"举例——示例即暗示，改成语义等价但域中立的表述，
> 并加了测试防止写回去。

没有第二份文档，这两个 bug 都不会暴露。

证据：`tests/test_cross_domain.py`、`data/prd/account-login-prd.md`

### Q12. 这东西能上量吗？贵不贵？

> 能跑，但**性能结论还没有**。批量跑 2 份文档 0.1s（31 份/秒）——这是 mock 的管道开销，
> 不调模型，不能当性能数字。真实延迟由 API 决定，限流与重试也没测。
> 成本方面有真实口径：单份优惠券 PRD 6 次调用、约 2.57 万输入 token / 1.24 万输出 token，
> 单价我不内置，用 `--price-in/--price-out` 传入才算钱。这样问"贵不贵"时给的是可复算的数，不是拍脑袋。

证据：`python run.py batch ...`、`python run.py cost --run <id>`

### Q13. 这个项目最大的弱点是什么？

三条，都能说：

1. **没有真实模型数据**：所有数字来自规则基线，真实模型的召回/格式合规率/成本都未测；
2. **基准集未经人工复核**：规模也只有 42 条，做不了统计显著性；
3. **没有生产接入**：用例库字段映射、权限、审计、公司历史用例都未接，
   离线跑通和"能落地"之间还差一大截。

### Q14. 如果重做，你改什么？

1. 先做评测装置再做生成（现在顺序对，但基准集应该更早介入）；
2. 匹配不用字符串相似度，改"场景要素抽取 + 要素级比对"（数值/状态/角色三元组），可解释得多；
3. 人工确认不做"改文本框"，做"勾选 + 批注"，改动才结构化，diff 才有语义。

## 红线：这些话不能说

| 不能说 | 为什么 | 可以说 |
|---|---|---|
| "AI 生成用例准确率 89%" | 那是评审分，不是准确率，且来自规则基线 | "评审分 89，但召回 2.4%，两者不相关" |
| "42 条人工标注基准集" | 还没人工复核过 | "42 条基准集，已过机器质检，待人工复核" |
| "采纳率 60%" | 没有人工裁决分母 | "采纳率未测，需要 30 条人工裁决" |
| "Fidelity 85%" | 代理指标不是语义判断 | "代理指标 X%，LLM judge 已实现但未做致率抽检" |
| "31 份/秒" | 那是管道开销，不调模型 | "mock 下 31 份/秒，仅反映管道开销" |
| "支持百万级 PRD" | 没测过 | "单机同步执行，批量并发只验证了产物隔离" |
