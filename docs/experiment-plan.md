## W1：接真实模型，拿到第一组真数据（3–4 小时）

| 步骤 | 命令 / 动作 | 产出 | 必须人工做的部分 |
|---|---|---|---|
| 1 | `.env` 填 `LLM_API_KEY`，`ATP_LLM_MODE=deepseek` | 能真实调用 | 确认账单/额度 |
| 2 | `python run.py run --prd data/prd/coupon-center-prd.md` | 停在闸门，看 AI 草稿 | **逐条检查功能拆分与规则**，至少改 3 处 |
| 3 | 页面里提交确认，观察下游 | 真实用例 + 评审 | 记录"哪类规则 AI 稳定漏" |
| 4 | `python run.py eval --prd coupon-center-prd --golden data/golden/coupon-golden.json` | 真实三模式对比 | 把 `reports/*.md` 数字填进 README |

**W1 验收**：README 里那张表换成真实数字，且能说出"bare → rag 提升多少、rag → rag_hitl 提升多少"。

## W2：把指标做实（4–5 小时）

1. **人工逐条裁决**（必须人做，不能 AI 打分）
   在控制台「③ 用例」里逐条点「可用/需修改/不可用」，至少覆盖 30 条 → 采纳率才有数。
2. **换 Fidelity 的实现**
   现在是启发式代理（只看数字是否带入）。接一个 judge 调用：
   `prompt: 给定需求原文与用例，判断用例是否忠实于需求（1–5 分），只输出 JSON`
   抽 10 对做人工复评，算 judge 与人的一致率（≥80% 才敢用）。
3. **阈值敏感性**
   把匹配阈值从 0.4 扫到 0.8，画出 Match Rate 曲线的陡峭段，说明 0.55 的选取理由。
4. **失败清单**
   把漏掉的基准点按类型归类（叠加规则/退款返还/时区/权限/幂等…），做成"AI 稳定失效的 5 类场景"表。

**W2 验收**：报告里有 4 个数（Match / Fidelity / 格式合规 / 采纳率），且失败清单能举 5 个具体例子。

## W3：包装与叙事（3–4 小时）

1. README 顶部换成真实结论（一句话 + 一张表 + 一张失败分类图）
2. 3 分钟演示视频脚本：闸门 → 改一条规则 → 下游用例变化 → 评审扣分点
3. 简历 bullet（`docs/resume-bullets.md` 里换成真实数字）
4. 面试 FAQ 过一遍（`docs/interview-faq.md`），每题能 60 秒讲完
5. 仓库整理：`git log` 干净、README 无占位符、`python -m pytest` 全绿

## 可选加分项（有余力再做）

- **跨文档泛化**：再找 1 份公开 PRD，只做 S1→S2，看召回是否骤降（证明"单文档过拟合"的自觉）
- **并发**：`ThreadPoolExecutor` 跑 5 份 PRD，记录总耗时与失败率
- **成本核算**：用 `llm_calls.jsonl` 里的字符数估算 token 与单份 PRD 成本，写进 README
- **回归防护**：把 `reports/*.json` 里关键指标写成断言，指标掉下阈值就让 CI 红
  （这是"给 AI 系统写测试"的元层：测的是 AI 的行为，不是 AI 的输出）

## 时间不够时的取舍顺序

1. 先保 **W1 真实数据**（没有真数字，整个项目就是空壳）
2. 再保 **W2 采纳率**（这是最贴地、最打动面试官的指标）
3. 可以砍 **W2 阈值敏感性** 和 **可选加分项**
4. 绝不能砍 **人工复核**（AI 自评自测等于没测）
